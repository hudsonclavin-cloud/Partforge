# Roadmap evaluation — the 50 ideas, scoped and attacked

One researcher scoped each of the 50 ideas. 8 then faced two independent skeptics — one checking the open-source and licence claims, one checking the engineering method and the effort — and 42 faced a single combined skeptic. A skeptic refuted something load-bearing in 34 of them, and where they did, the skeptic won unless the digest says otherwise.

Effort is engineer-days for one developer who already knows this codebase, with tests and the doctrine text the model has to be taught included. Value is 1 to 5 for a university rocket club making machined flight parts: 5 means they would use it on every part, 1 means a curiosity. Nothing here was measured. These are estimates that survived an attack, and anything that could only be recalled is marked.

Ideas 42, 43 and 44 — the motor, airframe and fastener databases — shipped while this evaluation was running, along with certified motor performance, ISO 286 fits, AS568 O-rings with their Parker glands, NPT, drills, 6061 stock, rails, altimeters and the material constants. See `data/README.md`.

> **Scope note (verified this session, 2026-09-18):** the repo has **no LICENSE or COPYING file** [Certain]. `data/tables/` contains **13** tables, not ten — `airframes, avionics, drills, fasteners_metric, fasteners_un, fits, materials_thermal, motor_perf, motors, npt, orings_as568, rails, stock` [Certain]. `index.html` is 7387 lines; **every line number in older scopes is off by roughly +35 — re-grep, do not trust them** [Certain].


## How to read this

**Value** is 1–5, post-skeptic: how much a correct implementation would change what the club can actually build, not how interesting it is. **Effort** is engineer-days for one developer who already knows this codebase, including tests and the doctrine/prompt-iteration loop that every original estimate under-priced by ~2×. Every number here survived a researcher pass, a skeptic pass and a re-derivation; claims I could not verify from a reachable host are tagged **[Recall]**, and the confidence tags **[Certain] / [Likely] / [Speculative]** mark non-obvious assertions throughout.

## What this evaluation already changed

The document below names defects in code that was shipping while it was being written. Three were
fixed the same day, before this file was committed, so read those entries as history:

- **The bolt-grade fallback** (wrong-number risk 1). `GRADE_SY` had no SAE grade-2 entry and fell
  back to 640 MPa, the strongest common grade — so the shipped bulkhead template's own grade-2
  U-bolt was checked 1.63x too strong. Grade 2 is now in the table at 393 MPa, and an unknown or
  undeclared grade **refuses** instead of defaulting. Declaring the truth then made that template
  fail at SF 1.86, so it now specifies a stainless A2-70 U-bolt and passes at 2.13 on the same
  conservative shear basis.
- **Recall data cited as a source** (wrong-number risk 2). The doctrine told the model to write
  `tol_src: "source"` for any reference-data dimension. It now ties provenance to the row's own
  confidence: `certain` and `likely` may be cited, `recall` may not, and the doctrine says why —
  161 of 291 airframe rows and 148 of 192 stock rows are recall.
- **Inch clearance holes typed into the prompt** (idea 44). The doctrine's own numbers were one fit
  class out: it called 6.76 mm the *normal* hole for 1/4 in, where ASME B18.2.8 makes 6.75 mm the
  *close* hole and 7.14 mm the normal one. Those numbers are deleted; the model is sent to the
  reference table, which ships them cross-checked. A test now fails if any of them reappears.

- **The QR code was drawn by a stranger's server** (the open-source section's note on
  `qrcode-generator`). The share link carries the whole part, base64 in the fragment, and it was
  being sent to `api.qrserver.com` to have a code drawn. For an app whose promise is that nothing
  leaves the browser, that was the worst line in the file. The code is now drawn on the device
  from a library loaded into the page, the dialog says so, and a blocked library produces an
  explanation rather than a silent fall back to the service.

Everything else below is open.

## Shared infrastructure

**This is the section that matters.** Fifty ideas collapse into eight foundations. Six of the eight cost under a week each, and together they unblock or de-risk 40 of the 50.

### A. A LICENSE file and THIRD-PARTY-NOTICES.md — 0.2 d
Unblocks: **everything**, legally. Named independently by all eight groups.
Today the repo is all-rights-reserved by default [Certain, verified], while it embeds Apache-2.0 `openrocket-database` data (attributed only through the `dbCredits()` UI string — Apache-2.0 §4 wants a License copy and a NOTICE file), ISC-declared `thrustcurve-db` derivatives, and loads GPL-2.0-or-later `openscad-wasm` from jsDelivr at runtime. No third-party MIT/ISC code can be vendored with a documented licence election (JSZip is `MIT OR GPL-3.0` — someone has to record which). The club cannot legally redistribute its own tool.

### B. Load-case / flight-envelope declaration — ~2 d
Unlocks or is a hard prerequisite for: **1, 2, 3, 4, 5, 6, 8, 10, 11, 12, 13, 14, 16, 17, 20, 21, 22, 23, 40, 41, 47, 48.**
One flight-condition block (v_max, altitude, q_max, Mach, max-Q station, motor designation) carried as `inputs_src: 'source'` with `inputs_ref` naming the club's OpenRocket or RASAero run, substituted into the existing checks by a sentinel. **This is the cheapest real win in the entire 50** [Certain]: the shipped doctrine still hard-codes `v_max_m_s 700 / alt_m 3000` and `force_N 12000–20000` as illustrative defaults, and those defaults are what the club's flutter and bolt-shear checks run on today. No simulator required.

### C. Non-gating row state + the retry-loop fixes — ~1.5 d
Unlocks: **1, 3, 5, 6, 8, 10, 11, 14, 15, 16, 18, 20, 28, 30, 31, 40.**
Three coupled defects. (i) `row.ok` initialises false and every `!row.ok` is pushed into `g.fails`, while `flightCounts` includes `loads.length` and `contractFloor` forbids a retry declaring fewer entries — so a *screening* or *refused* row is an unfixable hard fail that burns the whole retry budget. A buckling row on a G10 coupler is a deadlock today. (ii) `index.html:4939` reads `if(l.check !== 'thread') row.ok = row.sf != null && …` [Certain, verified], which overwrites any check that sets `row.ok` itself — every temperature-margin check fails until this is amended, and `:4943`'s "below the safety factor of" string plus the `:4945` hint ternary need arms too. (iii) The loads key copier filters on `/^[a-z_]+$/i` and 40-char-truncates non-numbers, so `I_mm4` is silently dropped and `excite_Hz: [lo,hi]` becomes `"80,200"`.

### D. Provenance that means something — ~2–3 d
Unlocks: **1, 2, 3, 5, 28, 30, 38, 42, 43, 44, 45, 47, 48.** Three parts of one problem.
- **Measured-input cross-reference.** A join from a loads entry to the CMM-measured `od`/`bores`/`critical-extent` rows by name or station. It does not exist: the evaluator reads `l.ri_mm` and `l.t_mm` straight off the declaration. **This is the single change that moves the loads table from "spreadsheet in a drawing" toward PartForge's actual thesis.**
- **Per-input provenance.** `inputs_src` is one field per loads *entry*, and `row.provisional = ok && inputs_src === 'default'` — so a row with a cited load and a guessed alpha carries the same tag as one where both are cited. Several proposed mitigations across the 50 are unbuildable without this.
- **Reference-table provenance state.** A `confidence: 'recall'` row must not be promotable to `tol_src: 'source'`. 161 of 291 airframe rows and 148 of 192 stock rows are recall [Certain, counted this session], and the shipped doctrine tells the model to cite them as vendor part numbers.

### E. Assembly / multi-part context (+ an angular datum feature) — idea 38 *is* this
Unlocks: **3, 4, 7, 8, 28, 29, 30, 38, 39, 45,** and most of "what the 50 missed."
Unsupported length between bulkheads, end fixity K, the mating flange's material and thickness, rod-borne avionics mass, the tube on the other side of every fit. A one-part file can never verify them. Separately: **no FLIGHT primitive declares an angular datum**, which is why clocking (two bolt circles 22.5° apart) is the one failure idea 38 structurally cannot catch, and why hole-pattern provenance is unreal even on single parts.

### F. 2D drawing layer + one shared document model — ~4 d of the 37 across 29/33/34/35
Unlocks: **29, 33, 34, 35** and the missing shop-traveler and first-article ideas.
Closed contours in mm (plane-mesh sectioning, pure JS) plus an annotation-placement pass, and — critically — **`drawingDoc()` landed BEFORE any second renderer**. `mfgSheet()` and `icdSheet()` must become thin renderers over one pure model, pinned by a byte-for-byte snapshot test. Without it the Markdown sheet, the SVG drawing, the DXF note block and the PDF disagree within a few revisions and nobody knows which document the part was cut from.

### G. Material data columns through the data/tables pipeline — ~3–4 d
Unlocks: **1, 2, 5, 8, 20, 21, 23, 28, 38.**
Already shipped: `nu`, `alpha`, `service_max_c` for all 21 materials (`materials_thermal.json`, `dbMaterialThermal()` at `index.html:4406`, `dbFitThermal()` at `:4410`) [Certain, verified]. Still missing: `k`, `cp`, **compressive allowables for laminates** (every laminate has `sy: null`), bearing allowables, hot-yield derates, notch class, **hoop CTE for laminates**, S-N constants. Two traps: laminate columns need a *direction* field (G10 through-thickness is 4–5× in-plane; a single CF number is meaningless), and `nu` derived as `E/2G−1` gives **1.27 for G10-FR4 and 1.68 for fibreglass laminate** from the shipped E and G columns — non-physical, and it corrupts idea 7's bending/torsion ratio and idea 9's elasticity matrix. Everything goes through `tools/db/build-*.mjs` + `embed.mjs` with per-row source/confidence; `tests/flight-db-embed.test.mjs` fails on drift.

### H. Record store, geometry digest and a central record path — ~3 d of the 34 across 45/46/47/48
Unlocks: **45, 46, 47, 48.**
The app has zero IndexedDB today [Certain, grep = 0 hits]; there is only a localStorage wrapper. Three shared requirements: a content-addressed object store with a Map adapter for Node; a **canonical geometry digest built from measured critical extents plus declared boundary parameters, NOT SHA-256 of `.scad` text** (the model rewrites comments on every retry, so a text hash marks every record stale immediately, and the staleness flag becomes noise); and a `crypto.subtle` fallback, since it is `undefined` over `file://`, a supported way to run this single-file app. Every one of these four ideas produces a record that lives in one student's browser profile — **the export bundle in the club's git repo is the only real record.**

### Minor but shared
A **mesh BVH** (`three-mesh-bvh`, MIT [Recall]) accelerates the existing ray-cast CMM, idea 33's plane sections and idea 36's ICP; the in-repo `buildMeshIndex`/`rayHits` is a 64³ uniform DDA grid, fine for hundreds of CMM rays and poor for 10⁵–10⁶. And the **doctrine/prompt-iteration budget**: every new FLIGHT key touches the clause list, the few-shot examples, the per-check missing-input ternary, ~9 embedded templates, 7 `.scad` files and `flight-templates-cases.json`, re-verified on two models. Every researcher budgeted 0.5–1 d; every skeptic priced it at 2 d+. **Believe the skeptics — this is the most consistent source of the 1.5× effort gap.**

## The licensing decision the repo has to make

**Current state [Certain, verified this session]:** no LICENSE, no COPYING, no NOTICE. Default copyright: all rights reserved. The app is published on GitHub Pages, embeds Apache-2.0 data attributed only in a UI string, embeds ISC-declared data whose upstream LICENSE file does not exist, and loads GPL-2.0-or-later `openscad-wasm` (with the CGAL linking exception) from a CDN at runtime.

**What the GPL question forces.** `index.html` is a single file that *is* the deliverable. There is no "link against" step to hide behind: any GPL code pasted into it makes the whole published page a GPL derivative. That means the mature implementation of almost everything on this roadmap — Barrowman CP, the Cd(M) build-up with its TR R-100 interpolators, `MassCalculator`, `Parachute.java`, openMotor's `ṙ = k·Pc`, CalculiX's eigen-buckling — is **permanently unavailable as code**. The trap is not the exotic CFD; it is the cheap alternative: the obvious way to write a Barrowman check is to read `BarrowmanCalculator.java`, and that one afternoon would relicense the club's tool.

**The line that stays open:** facts and numbers are not copyrightable expression. Running CalculiX or OpenRocket and copying *printed numbers* into unit tests creates no derivative work. Reading OpenRocket's motor loaders to learn that RASP `.eng` uses kg and RockSim uses g is fact-finding. Re-deriving a formula from Niskanen, Hoerner, Knacke or a NASA report and citing *that* is clean. **Transcribing a hand-fitted table out of GPL source is not.** `fasteners_metric.json`'s own provenance note already records cross-*checking* against NopSCADlib — that is fine; a transcription would not have been.

**Recommendation — one hour, do it before anything else:**
1. `LICENSE` = **MIT**. Permissive keeps the club able to fork, a sponsor able to use it, and costs only the GPL code that was never reachable anyway.
2. `THIRD-PARTY-NOTICES.md` listing openscad-wasm (GPL-2.0-or-later + CGAL exception, CDN-loaded, not vendored — **state this explicitly; the moment anyone vendors it or ships an offline bundle, the whole page becomes a GPL work requiring an offer of source**), three.js (MIT), openrocket-database (Apache-2.0, with a real `NOTICE`), thrustcurve-db (ISC by declaration, file absent — record the ambiguity).
3. Record every dual-licence election in writing (JSZip is `MIT OR GPL-3.0`; taking it silently leaves the choice undocumented).
4. **If STEP is ever built**, opencascade.js is LGPL-2.1 with the OCCT exception. Keeping the `.wasm` as a separate CDN-loaded artefact — the same pattern already used for openscad-wasm — satisfies relinking. But the OCCT exception requires a prominent notice **"in supporting documentation," which includes the manufacturing sheet and the ICD, not just the README** [Certain]. Plan for a licence line on the printed output.

## What the 50 missed

1. **Bonded joint and fin-tab bond-line shear.** Three separate skeptics independently named the through-the-wall tab and its bond line as where club fins actually fail. Nothing in 50 ideas computes epoxy shear area or peel at the tab and slot, and the app has nine tables of metal and zero adhesive data. Pairs naturally with idea 38's engagement math.
2. **The real recovery load path.** Three linked gaps: plate bending of a bulkhead between U-bolt legs (44.45 mm leg centres in a 146 mm disc — the governing mode both the existing `bolt_shear` row and the proposed lug check omit); **shear-pin sizing as a designed fuse** ("does it break at the right load," not "is it strong"); and vendor-rated hardware as *evidence* rather than analysis — for an eyebolt or quick-link the correct answer is an ASME B30.26 rating lookup, not a lug calculation. Parachute shock is statistically the commonest structural failure on club vehicles and every input is measurable on the part's own mesh.
3. **Nitrous self-pressurisation vs temperature.** The club machines N2O end caps. Saturated N2O runs ~5.1 MPa at 20 °C to ~6.9 MPa at 40 °C on a hot pad **[Likely]** — so MEOP for the *existing* Lamé hoop check is a strong function of pad soak temperature, and nothing connects the two. The highest-value thermal idea missed, and it reuses machinery that already ships.
4. **As-built / first-article inspection entry.** Type the caliper and CMM readings from the **machined** part back in and diff against the model. This is the missing half of the whole CMM story: every measurement in the app today is of the *mesh*, and nearly every idea in the 50 had to add that caveat. It is also the mechanism that turns every COMPUTED row into a real PASS row.
5. **"Will it fit the machine."** Spindle bore, chuck/collet capacity, mill travels and Z clearance against the part envelope. A hard geometric constraint the club hits on 150 mm bulkheads, nearly free on top of the existing `settings.envelope` check, and nobody listed it.
6. **Composite and layup outputs.** The club builds G10 fins and CF nose cones; the entire manufacturing group is metal-cutting and `stock.json` is aluminium-only, so buy-to-fly and stock-fit silently do not apply to a large share of real parts. Wanted: ply schedule, flat pattern, fin bevel templates, mould offset, and a **G10/G12 sheet and tube stock table**.
7. **Coating and plating dimensional allowance.** Type II anodise adds ~0.005–0.025 mm per side and grows a bore closed. It is on almost every club part, `mfg.finish` already names it as free text, and no idea treats it as a dimension — so it silently invalidates every fit idea 30 and 38 compute.
8. **Release package (.zip) + mass-properties export.** One download containing the `.scad`, STL/3MF, sheet or ICD, the JSON measurement report and a manifest with each file's sha256 — ~1 d, and it solves the "which file was this cut from" problem that four separate ideas keep re-encountering. Alongside it: emit an OpenRocket `.orc` entry or RocketPy JSON stanza from the mass/CG/inertia the app **already computes**, putting real machined masses into the flight sim instead of typed estimates (~2 d). The only export that feeds the vehicle model rather than the shop.
9. **Cutout knockdown for fin slots, vent and hatch openings.** The mode a plain SP-8007 shell check is constitutionally blind to, and where these airframes actually buckle.
10. **Cold soak and O-ring low-temperature flag.** Every thermal idea addressed the hot end. Buna-N goes glassy near −30 °C on a chilled nitrous fill, printed polymers embrittle, epoxy stiffens — and Parker's low-temperature gland guidance already ships inside `orings_as568.json`.

## Wrong-number risks

Ranked by how directly each could put a student under an unsafe vehicle. The first two are **live today**.

**1. Fastener grade fallback — shipping now. [Certain, verified at `index.html:4929`]**
`GRADE_SY` has no SAE grade-2 entry and defaults to 640 MPa; the shipped bulkhead template's own grade-2 U-bolt gets 640 instead of ~393 MPa — **1.63× non-conservative on the club's commonest recovery hardware.**
*Guard:* add grade 2 / A307 (and note that a bent U-bolt's rating is a vendor number, not a material number); half a day.

**2. Recall data printed as cited provenance — shipping now. [Certain, counted: 161/291 airframe rows, 148/192 stock rows, 29/124 motor rows]**
The doctrine instructs `tol_src: 'source'` with `tol_ref: '<vendor> <PN> (openrocket-database)'` for rows that are model recall. A club tube measuring 152.2 mm against a cited 152.4 gives a bulkhead that will not seat or a coupler that jams and fails to separate at apogee — and the mesh matches its declaration exactly, so the CMM pass, the loads checks and the release sheet all go green.
*Guard:* a provenance state recall rows cannot be promoted out of; a data-date on every hint line; print the synthetic-centering-ring caveat in the hint text, not only in the JSON.

**3. Composite allowables in compression checks (ideas 1, 2, 5).**
Every laminate has `sy: null`, so `needsYield()` throws into an **unfixable** retry deadlock; the natural fallback to `su` feeds a **tensile ultimate into a compression check** — 1.66× high for CF at su 500, up to 3.5× for a ±45 wound tube. And `E` is stored in GPa while σ_y is in MPa, so a slip in the Johnson denominator inflates SF and looks plausible because thrust loads are small.
*Guard:* metals only; refuse `kind: 'composite'` explicitly rather than letting it find a path; derive R and t from the measured `od`/`bores` rows, not declarations; print "compression (yield-limited)" whenever Johnson lands within 10% of σ_y.

**4. Certified peak thrust *lowering* the design load (idea 13). [Certain]**
Wiring the motor table in swaps a conservative `force_N 20000` "default" for an M1419W's 1591 N certified peak at factor 1.0 — an order-of-magnitude reduction wearing a better provenance label. Certified peak is a lot-mean of a finite-rate sampled curve with no ignition transient, chuffing or hard start; a sampled-curve maximum can be 2.4× *below* the certified peak (K543-BS: 900 N sampled vs 2129 N certified), and ~10% of current ≥54 mm motors have no certified peak at all.
*Guard:* the dynamic factor is **mandatory** — no factor, no evaluation, same treatment as a missing material; always `max_thrust_N`, never a curve maximum; **refuse** rather than fall back to average thrust when `max_thrust_src` is `'none'`; lint any declared `force_N` below the certified peak of a motor the request names.

**5. Recovery: Cd convention and recovered mass (idea 40). [Certain]**
Two conventions exist in the wild (Cd 0.8 on constructed area, 1.4 on projected radius) and a vendor's 2.2 is on nominal diameter; plugging any of them into the wrong formula, or declaring the 300 g bulkhead's own mass instead of the 10 kg section, sizes the canopy **3–30× small** and the sheet prints a clean diameter with a formula name. Separately, deployment velocity: main-at-drogue-speed (22 m/s) vs main-after-drogue-failure (60 m/s) is **7.4× in force** — the U-bolt shows SF 5 and the eyebolt lets go.
*Guard:* store Cd with its reference-area convention and require a canopy **type**, never a bare Cd; hard lint when declared mass is within 5% of the mesh mass; the late-deployment case is a **mandatory second row**; ejection rows print `ok = null` forever as a ground-test starting point.

**6. Aeroheating input substitution (idea 20).**
T₀ − T∞ tracks V²/2cp, not Mach, so accepting a bare `mach` lets "Mach 2 at apogee" read ~128 °C where the same vehicle at 3 km sees ~210 °C — an 80 °C unsafe-LOW read that passes a PA12 or G10 part.
*Guard:* `v_max_m_s` is the only speed input, M derived internally; **throw** when a material has no `service_max_c` rather than passing; print the row's `likely`/`recall` confidence beside the margin, because the shipped column is documented as judgement, not a rating.

**7. Ablative liner reported at the wrong instant (idea 21).**
"T_back 90 °C at burnout" is routinely 180 °C at the post-burn peak — and the 6061 temper is gone. Compounding: an under-estimated ṙ is subtracted from *both* the slab thickness and the SF numerator, so the error is non-conservative twice; and setting the hot-face T_s equal to flame temperature is a category error that over-sizes the liner while looking deliberate because the number came from a real source.
*Guard:* run to the peak, not to burnout; **refuse** `inputs_src: 'default'` for ṙ and h outright; print the erfc semi-infinite closed form beside the numeric answer as a units tripwire (α in m²/s vs mm²/s is 10⁶).

**8. Stock and fit comparisons against nominals (ideas 24, 27, 30, 38). [Certain]**
Extruded bar is minus-tolerant (6.000 in 6061: `dim_mm` 152.4, `dim_min_mm` 151.28, `max_finish_mm` 148.28) *and* a tessellated cylinder reads under nominal by the chordal tolerance — both errors push the same way, so a nominal-vs-nominal check prints "fits," the club buys the bar, and the recovery bulkhead ends up loose in the airframe.
*Guard:* gate on the **declared** nominal plus its tolerance against `dim_min_mm` / `max_finish_mm`; the mesh measurement is a cross-check only, and any disagreement between the two is itself a fault; derive the check by default so it fires on parts where nobody wrote a stock declaration — which is exactly where the mistake happens.

**9. Unverifiable inputs plus the retry loop (structural; hits 1, 3, 5, 6, 8, 28).**
Every failing loads row lands in `g.fails` and is handed back to the model with "correct the inputs if they were wrong." For any input with no geometric shadow — ΔT, bond `engage_mm`, fillet `r_mm`, Kt, ṙ — the model's cheapest fix is to edit the number. **The geometry stays byte-identical and nothing detects it.** Worse, `row.provisional` is tied to input *provenance*, not to whether anything was measured, so the "COMPUTED not PASS" mitigation evaporates the moment anyone writes `inputs_src: 'source'`.
*Guard:* an input that cannot be re-measured must be **refused**, not flagged provisional. Idea 5's proposed mitigation is the worst case of this arriving through its own fix: flooring a groove root radius to a *process capability* floor makes the printed Kt **lower** than reality.

**10. Documents that outrank the data behind them (ideas 33, 34, 35).**
A sheet that looks like a real drawing is trusted more than the Markdown it derives from. Any feature not on the section plane and not declared simply does not appear. Idea 34's volume-ratio prismaticity test passes two M4 counterbores at 0.11% each while the sheet says "the DXF fully defines the part." Idea 35's scale bar sits under a **perspective** capture unless the user happened to toggle orthographic. Idea 33's position-tolerance callout is uninterpretable without a datum reference frame that the design deliberately does not print.
*Guard:* a structural reconciliation line on every artefact ("this sheet dimensions N of N declared features; the `.scad` and `.stl` are the geometry of record; features not intersecting the section plane are not shown") with a count the shop can check; exact face-normal prismaticity, not a volume ratio; scale bars only on true-ortho views; **delete** the GD&T option rather than correct it.

**11. Av-bay vent lag (idea 41) — do not ship the number at all. [Certain, re-derived]**
The scoped `dh = (ρg/2)·(vV/(Cd·A·p))²` resolves to m⁴/kg, not metres; the correct form is `dh = (g/2)·(ρvV/(Cd·A·p))²` with ρ **inside** the square. Every worked figure in the scope is the true value divided by ρ — an error that hides at sea level where ρ ≈ 1 and grows to 2.4× at 10 km. Compounding: at the governing descent case the port sits at Re ~100–150 where a sharp-edged Cd is well under 0.3, not the cited 0.62, and dh scales as 1/(Cd·A)².
*Guard:* ship only the gauged vent holes and the PCB chord helper (~0.5 d). If the lag row is ever built, it must carry "pneumatic lag only; port location and the altimeter's Mach inhibit govern supersonic error; this does not certify deployment altitude."

**A closing note on the mis-citation trap.** Idea 2's *only* `verified: true` reference is cited wrongly: RocketPy's `evaluate_center_of_pressure` returns an **axial** station scaled by sweep length, not the spanwise arm a fin-root moment needs [Certain, file fetched by two independent passes]. Following the citation instead of the physics gives a silently wrong M_root. Treat every "verified" flag in this document as *the licence was checked*, not *the formula does what the citing text claims it does*.
